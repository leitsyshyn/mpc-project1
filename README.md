# Паралельна побудова зворотного індексу

Навчальний проєкт № 1 з дисципліни «Методи паралельних обчислень».
Виконав Тимофій Лейцишин, група ТТП-42.

Вміст архіву:

| Файл / каталог | Вміст |
| --- | --- |
| `report.pdf` | звіт |
| `results.csv` | результати всіх вимірювань |
| `README.md` | ця інструкція |
| `cmd/invindex/` | програма побудови індексу (версії V0–V4) |
| `cmd/falseshare/` | програма дослідження хибного розділення |
| `internal/index/` | реалізація версій, нормалізації тексту та формату виводу |
| `internal/bench/` | методика вимірювань (попередній запуск, повторення, медіана, запис у `results.csv`) |
| `scripts/` | завантаження корпусу і скрипти вимірювань |

Вихідний код версій:

| Версія | Файл | Опис |
| --- | --- | --- |
| V0 | `internal/index/v0.go` | послідовна, без синхронізації |
| V1 | `internal/index/v1.go` | багатопотокова без синхронізації |
| V2 | `internal/index/v2.go` | одна блокувальна змінна |
| V3 | `internal/index/v3.go` | секціоноване блокування, K блокувальних змінних |
| V4 | `internal/index/v4.go` | локальні індекси потоків і злиття (послідовне та деревом) |
| — | `internal/index/cas.go`, `internal/index/syncmap.go` | додаткові завдання: версія без блокувань і версія на основі `sync.Map` |
| — | `cmd/falseshare/main.go` | дослідження хибного розділення (реалізації A і B) |

## Перелік залежностей

- Go 1.26 або новіший (лише стандартна бібліотека, сторонніх модулів немає).
- Для завантаження корпусу: `curl`, `unzip`, `iconv`.
- Для скрипта `scripts/final.sh`: macOS (використовує `caffeinate`, `pmset`, `sysctl`).

Корпус текстів до архіву не додається. Його завантажує скрипт:

```sh
scripts/corpus.sh data 220 200
```

Аргументи: каталог для корпусу (`data`), мінімальний обсяг у МБ (`220`), мінімальна кількість файлів (`200`).

## Збирання

```sh
go build -trimpath -o bin/ ./cmd/invindex ./cmd/falseshare
```

Параметри компілятора:

- `-trimpath` — прибирає локальні шляхи з виконуваного файлу;
- `-o bin/` — каталог для виконуваних файлів `bin/invindex` і `bin/falseshare`;
- оптимізація та вбудовування функцій у компіляторі Go увімкнені за замовчуванням (аналог `-O2`), додаткових параметрів не потрібно;
- для вимірювань не можна використовувати `-race` і `-gcflags=-N -l`, які вимикають оптимізацію.

## Запуск

Побудова індексу версією V3 на 8 потоках з K = 1024:

```sh
bin/invindex -v v3 -p 8 -k 1024 -in data -out index.tsv -csv results.csv
```

Дослідження хибного розділення для реалізацій A (8 байт) і B (64 байти):

```sh
bin/falseshare -p 1,2,4,8 -stride 8,64 -n 10000000 -csv results.csv
```

Усі вимірювання зі звіту (близько 25 хвилин; потрібне живлення від мережі, сторонні застосунки слід закрити):

```sh
scripts/final.sh
```

Програма `invindex` зчитує корпус у пам'ять до вимірювання і записує індекс після нього, тобто вимірюється лише побудова. У стандартний потік помилок виводяться медіана, мінімальний і максимальний час, для V4 — час злиття, а також загальна кількість входжень, за якою визначаються втрачені оновлення у V1.

Формат вихідного файлу:

```
слово<TAB>загальна_кількість<TAB>doc17:12,doc3:5,doc41:1
```

## Опис аргументів

### invindex

| Аргумент | За замовчуванням | Опис |
| --- | --- | --- |
| `-v` | `v0` | версія: `v0`, `v1`, `v2`, `v3`, `v4seq` (V4, послідовне злиття), `v4tree` (V4, злиття деревом), `cas`, `syncmap` |
| `-p` | `1` | кількість потоків (для `v0` не використовується) |
| `-k` | `1024` | кількість блокувальних змінних K (лише для `v3`) |
| `-in` | `data` | каталог із корпусом |
| `-out` | `index.tsv` | вихідний файл індексу |
| `-warmup` | `1` | кількість попередніх запусків, які не враховуються |
| `-repeat` | `5` | кількість вимірюваних повторень |
| `-csv` | — | файл, до якого дописуються результати вимірювань |
| `-tokenizer` | `swar` | функція нормалізації: `swar` (`FastWords`) або `std` (`Words`) |
| `-cpuprofile` | — | файл для профілю процесорного часу (`go tool pprof`) |

### falseshare

| Аргумент | За замовчуванням | Опис |
| --- | --- | --- |
| `-p` | `1,2,4,8` | кількості потоків через кому |
| `-stride` | `8,16,32,40,64,128,256` | відстані між лічильниками в байтах через кому; 8 — реалізація A, 64 — реалізація B |
| `-n` | `10000000` | кількість інкрементів на потік |
| `-warmup` | `1` | кількість попередніх запусків |
| `-repeat` | `5` | кількість вимірюваних повторень |
| `-csv` | — | файл, до якого дописуються результати вимірювань |

### Скрипти

| Скрипт | Призначення |
| --- | --- |
| `scripts/corpus.sh [каталог] [МБ] [файлів]` | завантаження корпусу з Project Gutenberg |
| `scripts/final.sh` | усі вимірювання; результати записуються в `results.csv` |
| `scripts/bench.sh [експеримент...]` | масштабування версій і залежність V3 від K; кожен вихідний файл порівнюється з результатом V0 |
| `scripts/v1-lost-updates.sh [P...]` | 10 запусків V1 для кожної кількості потоків і порівняння з V0 |
| `scripts/supplementary.sh` | контрольні вимірювання для V3 |

## Файл results.csv

Стовпці: `program, version, threads, k, run, seconds`. Крім назв версій, використовуються позначки:

| Позначка | Вимірювання |
| --- | --- |
| `v0-std`, `v4tree-std` | з функцією нормалізації `Words` |
| `v4seq-merge`, `v4tree-merge` | час злиття у V4 |
| `stride-N` | хибне розділення, відстань N байт, 10 млн інкрементів |
| `stride-N-200M` | те саме, 200 млн інкрементів |
| `v0-notop20`, `v3-notop20` | корпус без 20 найчастотніших слів |
| `v3-padded`, `v3-unpadded` | V3 за P = 8 із заповнювачем і без нього |
